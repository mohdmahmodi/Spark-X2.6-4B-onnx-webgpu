Spark-X2.6-4B in the browser

A 4-bit ONNX build of Spark-X2.6-4B that runs entirely on the GPU in Chrome or Edge, with no server and no install. It scores the same as XHToken's official INT4 model on math, function calling and long-context retrieval.

Get started

The model is a folder of static files and the loader is a few JavaScript modules. There is no build step and no server code.

  1. Chat in the browser

    Open the chat in desktop Chrome or Edge. The model downloads once (2.77 GB) and loads from the browser cache afterwards.

  2. Run it locally

    Serve the app from a clone. It loads the model from Hugging Face unless a local build exists.

    git clone https://github.com/mohdmahmodi/Spark-X2.6-4B-onnx-webgpu
cd Spark-X2.6-4B-onnx-webgpu
npm install
npm run serve

  3. Use it in your own app

    Copy web/lib/ and the import map from web/index.html. generate streams text and accepts temperature, maxNewTokens, effort, tools and an abort signal. 

    import { loadSpark } from "./lib/spark.js";

const spark = await loadSpark({
  base: "https://huggingface.co/mohdmahmodi/Spark-X2.6-4B-ONNX-WebGPU/resolve/main",
});

const messages = [{ role: "user", content: "Hello!" }];
for await (const text of spark.generate(messages, { thinking: false })) {
  output.textContent += text;
}

Requirements

Browser
Chrome or Edge 113 or later on desktop, with WebGPU. GPUs without shader-f16 load the fp32-activation build automatically.
GPU memory
About 3.5 GB at 4k tokens of context: 2.77 GB of weights and 0.6 GB of cache per 4k tokens.
Buffer size
At least 336 MB per storage buffer, for the embedding table. Many phones and older GPUs allow less.
Not supported
The WebAssembly (CPU) backend in browsers, which has no kernel for the quantized embedding.

Method

Every browser number comes from the real page driven by headless Chrome, with token ids checked against transformers on every prompt.

Reference
XHToken/Spark-X2.6-4B in transformers (bf16), and the official Spark-X2.6-4B-INT4 weights in transformers.
GSM8K
All 1,319 test problems, zero-shot, thinking off, scored on the final number.
Function calling
The first 200 "simple" cases of BFCL v3, in Spark's tool-call format, parsed with the rules of SGLang's spark25 parser.
Long context
A passphrase placed at the start, middle or end of 1k, 4k, 8k and 16k tokens of Wikipedia text.
Logits
20 prompts at 8 positions each. The build adds a mean KL divergence of 0.0003 on top of the INT4 quantization.
Stability
30 minutes of back-to-back generations: 683 replies and 122,745 tokens with no errors, no slowdown and flat GPU memory.
Model quality
The comparison with other models is XHToken's, measured on the original model with thinking on. It was not re-run here.
Not yet covered
macOS, Android, other GPUs, and benchmarks with thinking on for this build.
Full report
Per-system tables, the largest divergences side by side, and scripts to reproduce every number: VALIDATION.md.
